# 猫咖局内表现技术总结

本文总结局内四类核心表现：辉光、金币散射、转盘和金币收集。

## 1. 辉光

### 实现

- 使用 `CatCafePieceSoftGlow.shader` 读取棋子 RGBA 图集的 alpha，避免为每个棋子单独制作遮罩。
- 顶点阶段按 `_GlowSize` 扩张几何体，保证辉光有足够的屏幕覆盖范围。
- 片元阶段采样 8 层环形壳（每层 8 个方向，共 64 次采样），由内到外逐层降低权重，形成“中心亮、边缘柔、越往外越淡”的效果。
- 使用 `Blend SrcAlpha One` 做加法混合，并由 `CatCafeUiBloomBootstrap` 开启 HDR/Bloom，让高亮区域产生真实的泛光。

### 小巧思

- 相邻壳层交替使用轴向和偏移角度采样，减少放射状条纹。
- `CatCafeGlowPulse` 只让透明度和 HDR 强度呼吸，辉光尺寸固定在配置的峰值；棋子放大或缩小时，外圈不会继续变大。
- 淡入、呼吸、淡出都使用非线性曲线，避免突然出现或消失。

### 当前关键参数

- 材质：`_GlowRadius=21.2`、`_GlowSoftness=15.12`、`_GlowSize=24`、`_GlowEmission=8`。
- Bloom：阈值 `0.9`、强度 `0.8`、散射 `0.85`、限制值 `12`，色调偏暖金色。

## 2. 金币散射

### 实现

- `CatCafeRareChainCoinBurst` 使用 UI `Image` 渲染金币，和 Screen Space Camera 画布保持同一坐标系。
- 金币从触发棋子位置向四周发射，初速度带随机角度和速度；随后叠加重力，形成轻微抛物线。
- 每枚金币的尺寸、重力、旋转速度和淡出起点独立随机，避免整齐复制感。
- 金币对象按数量预创建并复用，结束后隐藏，减少运行时 Instantiate/Destroy。

### 小巧思

- 6 枚金币按圆周方向分布，同时加入小角度抖动，既有爆发感又不显得机械。
- 淡出起点按序列错开，形成“前后层次”，而不是所有金币同时消失。
- 散射生命周期跟随当前结算节拍（`settlement_rare_chain_coin_lifetime_multiplier`），加速结算时不会拖慢流程。

### 数据驱动

金币数量、大小范围、速度范围、重力、旋转、淡出和资源路径均从 `cat_cafe_config.json` 读取；当前稀有联锁默认散射 6 枚金币。

## 3. 转盘效果

### 实现

- 棋盘切换时暂时隐藏静态棋盘，显示按列组织的 Reel Overlay；每列包含可循环复用的符号条带和裁剪视口。
- 各列以 `0.045s` 间隔错峰启动，制造连续转动的节奏。
- 单列动画分为三段：
  1. 预备位移：先向反方向轻拉，建立蓄力感。
  2. 主运动：按缓动曲线移动到目标附近，列号越靠后总时长略增加。
  3. 停止回弹：越过目标后用衰减弹簧回到准确位置。
- 所有中间帧使用 `Time.unscaledDeltaTime`，暂停或时间缩放时仍能保证 UI 演出完整。

### 小巧思

- 预览条带提前填充最终棋盘和随机符号，滚动时不会露出空白。
- 停止阶段同时做极轻微的纵向缩放（约 `1.2%`），让落点更有重量，但不改变棋盘布局。
- 动画结束后再恢复静态棋盘并关闭 Overlay，避免两个渲染层长期叠加。

## 4. 金币收集

### 实现

- 收集流程为：来源处弹出金额标签 → 金币分批生成 → 每枚金币沿二次贝塞尔曲线飞向顶部金币 HUD → 抵达后触发入账回调。
- 奖励金额拆成 `1~6` 枚金币，并用“整除值 + 余数”分配，保证总额精确不丢失。
- 起飞阶段先做短距离爆发，随后进入带磁吸感的曲线飞行；飞行中同步旋转、缩放脉冲、局部高光和多段拖尾。
- 通用奖励会按飞币抵达逐笔入账；棋盘批量结算则在每枚棋子的整组飞币完成后入账，顶部金额持续变化，而不是整轮结束后一次跳变。

### 小巧思

- 二次贝塞尔控制点加入横向偏移和上拱高度，金币路线既有随机性又稳定指向 HUD。
- `magneticT = t^1.68` 让前段更舒缓、后段更快收束，强化“被吸入”的感觉。
- 金币、拖尾和标签都有对象池；资源缺失时只在当前会话生成临时图标，并明确输出警告。
- 结算按同价批次组织，批次间保留短暂停顿和高亮，让玩家能读懂每一组收益来源。

### 时序参数

结算提示和批次停顿由表格控制：收集前提示 `0.24s`、批次高亮 `0.14s`、批次停留 `0.14s`、批次间隔 `0.08s`、最终入账提示 `0.36s`。

## 共通设计原则

- 所有演出都运行在固定 `16:9`、`1536×864` 参考画布上，坐标和点击区域不随比例重排。
- 奖励数值、文案、资源路径和结算节奏优先从正式配置表读取；代码只负责通用动画和流程编排。
- 高频对象优先池化，减少 GC 和 Canvas 层级抖动；动态创建的运行时资源在销毁时清理。
- 保持源资产尺寸、透明通道和清晰度，不通过压缩或降采样换取效果。
