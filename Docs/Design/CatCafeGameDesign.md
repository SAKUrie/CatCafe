## 1. 定位与世界观

### 1.1 一句话

经营一家猫咖：每回合"营业"一次，猫、客人、餐饮和道具被随机摆上一张 4×4 桌台，
靠**元素之间的相邻关系**结算金币，在三个阶段的截止日前付清房租。

### 1.2 世界观现状

目前的世界观是**轻叙事的氛围设定**，没有剧情、没有角色台词、没有反派或冲突链。全部世界观文本
集中在开始界面（`CatCafeStartController.cs`）：

| 位置 | 文案 |
| --- | --- |
| 标题 | 猫咖营业计划 |
| 副标题 | 把猫咖经营成为城里最热闹的角落 |
| 卖点 1 | 三选一：每回合挑一项奖励 |
| 卖点 2 | 连锁收益：摆放相邻元素赚取金币 |
| 卖点 3 | 阶段目标：完成三关后进入自由经营 |
| 开始按钮 | 开始营业 / "点击开始，开始今天的经营" |

隐含设定可以从元素表反推出来：

- **场所**：一家城里的猫咖，有店面、桌台、员工（咖啡师）、常客与流动客人。
- **玩家身份**：店长。玩家做的是"进什么货、留哪只猫、送养谁"，不是操作角色。
- **猫的地位**：猫既是员工也是招牌。猫会被客人吸引产生小费收益，会喝掉温牛奶，
  会在育儿窝里繁育出幼崽，幼崽收益更高但不能再繁育。
- **时间尺度**：一个"回合"= 一次营业时段；一个"关卡"= 一段营业期（5~6 回合），
  期末要向店面付一笔钱（房租/进货款）才能续营。
- **基调**：治愈、像素、暖棕色调（UI 主色 `#6E4C38` 系），无失败惩罚叙事——
  没达标就是"重新开店"。

### 1.3 与仓库名的历史落差

描述的都还是**上一代概念**（2D 伪装/变脸解谜，"根据线索选择合适的脸骗过检查"）。

## 2. 核心玩法循环

### 2.1 关键认知：玩家管的是"牌库"，不是"摆位"

这是理解全部数值的前提。棋盘**每回合完全重排**：

```
RunRound():
  1. 从 pool（店内清单）洗牌，取前 16 个，不足补空位，再整体洗一次 → 新的 4×4 棋盘
  2. 老虎机式转轴动画逐列停下
  3. 按棋盘下标顺序结算每个元素的收益（逐个飘金币）
  4. 处理消耗品（温牛奶被相邻猫喝掉）
  5. 结算繁育（育儿窝 → 幼崽）
  6. 结算回合末物品（安静时段铃、黄铜收银机）
  7. 回合数 +1，判断阶段截止
  8. 未截止 → 弹出三选一奖励；已截止 → 结算关卡
```

玩家**无法决定任何元素的位置**。开始界面写的"摆放相邻元素"略微夸大了操作权——
玩家真正的决策是：

1. **三选一**往清单里加什么（构筑）
2. **送养券**从清单里删什么（洗牌库/提高命中率）
3. **换牌券**刷新三选一
4. 关卡间选哪件**经营物品**（全局修正器）

因此这是一个 **Slot-machine 驱动的 deckbuilder**：相邻收益是概率期望，
不是玩家可规划的布局。清单越臃肿（>16），每回合能上桌的比例越低，
所以"送养"（deck thinning）是核心操作之一。

### 2.2 起始状态

| 项 | 初始值 |
| --- | --- |
| 店内清单 | 黑猫 ×1、白猫 ×1、橘猫 ×1、客人 ×3 |
| 金币 | 0 |
| 换牌券 | 1 |
| 送养券 | 1 |
| 经营物品 | 无 |
| 阶段 | 第 1 关「试营业」 |

**实现细节**：第 1 回合结束后的首次三选一，若清单里没有育儿窝，会**强制**把第一个
选项替换成「育儿窝」（`RewardOptions`：`round == 1` 分支）。这是一条隐藏的新手引导，
保证玩家早期接触繁育系统。

## 3. 棋盘与相邻规则

- 棋盘：4×4 = 16 格，下标 `index`，`row = index / 4`，`column = index % 4`。
- **默认相邻 = 上下左右 4 格**（正交）。
- 例外一：**育儿窝**判定繁育时永远看**周围八格**。
- 例外二：持有**落地观景窗**后，**猫咪、幼崽、咖啡**这三类在计算自己的收益时改看八格。
  注意这是**单向**的——只有"赚钱的那一方"视野扩大，被数的元素不受影响。
- **成套坐垫**的成组判定用正交连通（BFS，`ConnectedSameCount`），同名元素连成 ≥3 个即触发。

## 4. 元素图鉴（27 种）

### 4.1 成年猫（Kind = Cat）

所有成年猫共有基础规则：**每 1 名相邻客人 → 2 金币**。
统一公式（含猫粮加成）：

```
收益 = 相邻客人数 × (2 + 相邻猫粮数) + 专属加成
```

| 元素 | 稀有度 | 色系 | 专属加成 | 美术 |
| --- | --- | --- | --- | --- |
| 黑猫 | 普通 | black | — | `black-cat` |
| 白猫 | 普通 | white | — | `white-cat` |
| 橘猫 | 普通 | orange | — | `orange-cat` |
| 灰虎斑 | 普通 | gray | 每 1 个相邻**道具** +1 | `gray-tabby-cat` |
| 燕尾服猫 | 少见 | tuxedo | 恰好相邻 1 名客人时 +2 | `tuxedo-cat` |
| 奶牛猫 | 少见 | cow | 每 1 份相邻猫粮 +3 | `cow-cat` |
| 三花猫 | 稀有 | calico | 每 1 只相邻猫咪 +1 | `calico-cat` |

### 4.2 幼崽（Kind = Kitten，稀有度 Special）

- 基础规则升级为**每 1 名相邻客人 → 3 金币**（同样吃猫粮加成：`客人 × (3 + 猫粮)`）。
- **不能参与繁育**。
- **无法从三选一获得**——Special 稀有度不在奖励池里，只能靠育儿窝产出。

| 幼崽 | 色系 | 复用的美术 |
| --- | --- | --- |
| 黑色幼崽 | black | `blue-gray-cat` |
| 重点色幼崽 | white | `siamese-cat` |
| 虎斑幼崽 | orange | `brown-tabby-cat` |
| 白袜黑猫 | tuxedo | `white-socks-cat` |
| 玳瑁幼崽 | tortie | `tortie-cat` |
| 橘白幼崽 | orangeWhite | `calico-cat` ⚠️ 与三花猫撞图 |
| 混色幼崽 | mixed | `gray-tabby-cat` ⚠️ 与灰虎斑撞图 |

### 4.3 客人与餐饮

| 元素 | 类型 | 稀有度 | 规则 | 美术 |
| --- | --- | --- | --- | --- |
| 客人 | 客人 | 普通 | 小费：每回合固定 +1 | `guest` |
| 咖啡 | 餐饮 | 普通 | 每 1 名相邻客人 +2 | ✗ 缺 |
| 猫爪点心 | 餐饮 | 普通 | +1；每 1 名相邻客人再 +1；相邻 ≥2 客人额外 +2 | ✗ 缺 |
| 温牛奶 | 消耗品 | 普通 | 相邻有猫时 +6，**生效后从清单永久移除** | ✗ 缺 |

### 4.4 猫咪用品

| 元素 | 稀有度 | 规则 | 美术 |
| --- | --- | --- | --- |
| 猫粮 | 普通 | 自身不产出；给相邻猫咪的**每次服务** +1（乘在客人数上） | `cat-food` |
| 猫砂盆 | 普通 | 每 1 只相邻猫咪 +1 | `litter-box` |
| 逗猫棒 | 普通 | 每 1 只相邻猫咪 +2 | ✗ 缺 |
| 猫爬架 | 少见 | 每 1 只相邻猫咪 +2；相邻 ≥3 只额外 +3 | ✗ 缺 |
| 育儿窝 | 少见 | 自身不产出；八格内 ≥2 只成年猫时**变成幼崽** | `nursery-bed` |

### 4.5 员工与经营道具

| 元素 | 稀有度 | 规则 | 美术 |
| --- | --- | --- | --- |
| 咖啡师（Staff） | 少见 | 每 1 名相邻客人 +1；每 1 杯相邻咖啡 +3 | ✗ 缺 |
| 小费罐 | 少见 | +1；**场上**每 2 名客人再 +1 | ✗ 缺 |
| 招财铃 | 稀有 | 同时相邻 ≥1 猫且 ≥1 客人时 +8 | ✗ 缺 |
| 领养海报 | 稀有 | **场上**每 1 种不同猫毛色 +1（含幼崽色系） | ✗ 缺 |

> 小费罐与领养海报是唯二**全局（看整张棋盘）**而非看相邻的元素。

## 5. 繁育系统

结算时机：每回合所有收益结算完之后（`SettleBreeding`）。

1. 扫描棋盘上所有**育儿窝**（按下标顺序）。
2. 取该育儿窝**八格**内、**尚未被本回合其他育儿窝占用**的成年猫（`Kind == Cat`，幼崽不算）。
3. 不足 2 只 → 跳过；≥2 只 → 随机洗牌取前两只作为亲代，标记为已占用。
4. **育儿窝本体转化为幼崽**（棋盘与清单中同步替换），亲代猫不消耗。

### 色系遗传表

| 亲代组合 | 产出 |
| --- | --- |
| black + black | 黑色幼崽 |
| white + white | 重点色幼崽 |
| orange + orange | 虎斑幼崽 |
| black + white | 白袜黑猫 |
| black + orange | 玳瑁幼崽 |
| orange + white | 橘白幼崽 |
| 其他任意组合 | 混色幼崽 |

**实现细节**：遗传表只认 black/white/orange 三个基础色。灰虎斑（gray）、燕尾服猫（tuxedo）、
奶牛猫（cow）、三花猫（calico）参与繁育时，任何配对都落到「混色幼崽」兜底分支。
也就是说**高稀有度的猫在繁育上反而没有色系价值**，这是一个明显的设计缺口。

## 6. 关卡结构与经济

### 6.1 三个阶段

| 关卡 | 名称 | 回合数 | 目标金币 |
| --- | --- | --- | --- |
| 1 | 试营业 | 5 | 35 |
| 2 | 午后客流 | 5 | 85 |
| 3 | 周末满座 | 6 | 175 |

- 金币**跨关累计**，不清零。
- 关卡截止时：`money >= target` → **扣掉 target**（付房租），继续；否则失败。
- 失败 → "重新开店" → `ResetGame()`，**整局从零开始**（清单、物品、金币全清）。
- 应急保温壶：截止时金币不足且持有该物品 → 消耗它，**本关 +1 回合**，可救一次。
- 通关第 3 关 → 进入**自由经营**（endless）：无目标、无截止，回合数显示为 `n+`。

### 6.2 关卡奖励

清关（非失败）时结算：

1. 扣除目标金币
2. 换牌券 +1、送养券 +1
3. 弹出**经营物品三选一**
4. 紧接着弹出**元素三选一**，且带**最低稀有度保底**

| 事件 | 物品池档位 | 元素保底 |
| --- | --- | --- |
| 通过第 1 关 | tier 0 | 至少「少见」 |
| 通过第 2 关 | tier 1 | 至少「稀有」 |
| 通过第 3 关（通关） | tier 2 | 至少「稀有」 |

### 6.3 代币

| 代币 | 初始 | 获取 | 用途 |
| --- | --- | --- | --- |
| 换牌券 | 1 | 每次清关 +1 | 三选一「换一批」刷新 |
| 送养券 | 1 | 每次清关 +1；循环回收桶每消耗 3 个元素 +1 | 在「店内清单」里删除 1 个元素 |

送养限制：结算期间（`locked`）不可用；清单只剩 1 个元素时不可用。

## 7. 经营物品（13 件，全局修正器）

物品**一旦获得永久生效**，唯一例外是应急保温壶（触发后消耗）。同一件物品不会重复出现在选项里。

| 物品 | 稀有度 | 效果 |
| --- | --- | --- |
| 猫咪围裙 | 普通 | 所有猫咪和幼崽每次产生收益时 **+1** |
| 招财猫摆件 | 普通 | 清单内每只猫使少见/稀有权重 **×(1 + 8% × 猫数)** |
| 集点卡 | 普通 | 每次从三选一加入元素时 **+2 金币** |
| 零食陈列架 | 普通 | 温牛奶和猫爪点心每次产生收益时 **+2** |
| 安静时段铃 | 普通 | 本回合总收入 ≤12 时，回合末 **+4** |
| 成套坐垫 | 少见 | 同名元素正交连通 ≥3 个时，它们的收益 **×2** |
| 循环回收桶 | 少见 | 每消耗 3 个元素 → **+8 金币、+1 送养券** |
| 落地观景窗 | 少见 | 猫咪、幼崽、咖啡的相邻判定扩展到**八格** |
| 双层托盘 | 少见 | 每回合**第一个**被消耗元素的收益 **×2** |
| 应急保温壶 | 少见 | 关卡截止金币不足时消耗自身，**+1 回合** |
| 本店招牌套餐 | 稀有 | 场上 ≥3 猫且 ≥3 客人时，咖啡/点心/咖啡师收益 **×2** |
| 预约名册 | 稀有 | 元素奖励从 3 个选项变 **4 个** |
| 黄铜收银机 | 稀有 | 每回合末，**每持有 1 件经营物品 +1 金币** |

### 单元素收益的结算顺序（`CalculateEvents`）

顺序影响最终数值，加算必须先于乘算：

```
1. 基础规则（含猫粮：客人数 × (2或3 + 猫粮数)）
2. 专属加成（灰虎斑/燕尾服/奶牛/三花）
3. + 猫咪围裙（猫、幼崽 +1）
4. + 零食陈列架（温牛奶、猫爪点心 +2）
5. × 本店招牌套餐（咖啡、点心、咖啡师，条件满足时 ×2）
6. × 成套坐垫（同名连通 ≥3 时 ×2）
7. × 双层托盘（仅本回合首个消耗品）
→ amount <= 0 的元素不产生结算事件（不飘字、不停顿）
```

回合末独立结算（`SettleRoundItems`）：安静时段铃 + 黄铜收银机，合并成一次飘金币。

## 9. 表现层

- **运行时构建 UI**：场景里只需要 Camera、EventSystem 和挂了 `CatCafeGameController` 的
  根节点，Canvas 与所有面板都由代码生成。参考分辨率 1600×900（16:9，`matchWidthOrHeight = 0.5`）。
- **布局契约**：HUD 横跨顶部（金币/关卡/目标/回合四块）；主机体固定 790×690 居中，
  内含 540px 的 4×4 棋盘框；对话面板 600px，卡片行 360px、单卡 112px、操作行 330px。
- **老虎机转轴**（`AnimateBoardRoll`）：4 列独立转轴，起转错开 0.045s，
  基础时长 1.28s 且每列递增 0.18s，带回拉预备动作（10px / 0.09s）、
  停止过冲 13px 与 0.24s 弹性回弹，列停时有纵向 punch 缩放。转轴符号从当前清单
  （含空位占比）随机预览。
- **金币飞行特效**（`CatCafeRewardFx`，705 行）：从产出格飞向 HUD 金币位，
  对象池化（拖尾、数字、硬币、光斑四类），金币抵达时才真正加钱（`onCoinArrived` 回调）。
- **像素风框线**：统一用 `Outline` 组件做 3px 硬阴影（`PixelFrame`），
  美术导入为 point filter。
- **Toast**：单行提示，复用一个 `Text`。

### 值得注意的边界行为

- **满桌加入元素**：三选一后新元素放进第一个空格；若棋盘已满（清单 ≥16），
  改为**随机覆盖一格**（`Choose()`：`empty = Random.Range(0, BoardSize)`）。
  被覆盖的元素仍留在清单里，只是本回合不再显示。
- **清单无上限**：清单可无限增长，但每回合只有 16 个能上桌，
  超出部分形成稀释。送养券是唯一的缩表手段。
- **收益为 0 不飘字**：`amount <= 0` 的元素直接跳过，所以孤立的猫、
  没有相邻猫的温牛奶在表现上"什么都没发生"。
- **温牛奶双重移除**：触发后同时从棋盘和清单删除，属于一次性消耗品。
