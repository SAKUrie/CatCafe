# 猫咖营业计划 · 局外成长系统设计

> 数据入口已统一为 `GameDesign/CatCafeGameConfig.xlsx`；本文提到的旧 CSV 文件名请对应到工作簿同名数据页。

> 配套文档：[CatCafeGameDesign.md](CatCafeGameDesign.md)（局内现状逆向整理）、
> [MetaGameTechDesign.md](MetaGameTechDesign.md)（技术设计）、
> [DataTableSpec.md](DataTableSpec.md)（策划写表接口与美术规范）。
> 本文是设计定案：局内保持幸运房东式随机合成经营不动，局外新增「收集 + 养成 + 展示」长期循环。

---

## 0. 核心定位

玩家身份：**经营猫咖的店长**。通过一局局营业赚钱、邂逅并繁育猫咪，扩建自己的猫咪收藏馆。

核心卖点不是"玩一局赚金币"，而是：

> **"我想看看下一次营业能不能繁育出一只新的猫。"**

整体循环：

```
        局外猫咖（Home）
   收集图鉴 / 培养猫咪 / 展示装修
             │
             ▼
        开始一次营业挑战
             │
   幸运房东式随机棋盘经营（局内，不改核心）
             │
    金币 → 罐头 │ 繁育 → 发现新猫 │ 重复 → 绒毛
             │
             ▼
   填图鉴 / 呼朋唤友请新朋友 / 培养喜欢的猫
             │
             └────── 下一局继续追新猫 ──────┐
```

## 1. 已拍板的设计决策

| # | 决策 | 内容 |
| --- | --- | --- |
| D1 | **奶牛猫、三花猫、燕尾服猫移出默认奖励池** | 改为繁育专属发现。图鉴解锁后才进入局内奖励池。灰虎斑保留在普通池（双来源）。 |
| D2 | **确定遗传表为主 + 变异位** | 基础配对结果确定可预期；每次繁育附带小概率变异出稀有种。高级猫走"确定的特殊配方"（可主动凑条件），不走纯概率。 |
| D3 | **发现幼崽 = 解锁该品种成年形态** | 局内诞生的幼崽保持幼崽规则（+3/客人、不繁育）；局末"长大"进图鉴。此后该品种**成年形态**可出现在奖励池，可参与繁育、携带自己的基因——二级遗传树由此展开。 |
| D4 | **亲密度取代购买式升级**（2026-08-13） | 养成主线是"同行营业"自然增长（同行完局 +1、首次发现 +2、繁育出后代 +1），辅线是喂食（罐头，带冷却）。不存在花资源买等级。详见 §6。 |
| D5 | **现有 perk 迁移**（2026-08-13） | `mutation_up`、`material_bonus` 平移进亲密度里程碑（本就横向）；`board_weight` 从被动常驻改为**随行猫限定**；levels.csv 的罐头/绒毛消耗列作废，绒毛回归纯合成材料。**永不引入**局内收益类 perk（income_up 之流）。 |
| D6 | **随行猫 = 局前选择的唯一承载体**（2026-08-13） | 开始营业前从入住猫中指定一只随行：获得上场加权 + 该猫的亲密度满级横向特性。一次只有一只生效，天然防"全队叠被动"。取代二期 backlog 的"镇店猫"。 |
| D7 | **亲密度内容闸门**（2026-08-13） | 里程碑节奏全品种统一（表驱动模板）；差异化内容仅两处：故事文本（`dex_flavor` 已有列）与满级特性。MVP 只为 3–5 只基础猫配特性，其余显示"？？？"（本身即收集钩子）。 |
| D8 | **世界观与体验框架**（2026-08-13） | "一家店，两种状态"（营业中/歇业门牌，**昼夜设定已否决**）；幸运房东为规则化身（仅文案+字条层级）；客猫与住猫；挂起存档（退出=时间暂停）。同日补充：**主角是店长猫**；房东是和蔼老太太「房东奶奶」，新手教学由她的字条承载（文案已定稿）。详见 [WorldAndExperience.md](WorldAndExperience.md)（教学=§8）。 |
| D9 | **呼朋唤友取代局外合成**（2026-08-15） | 局外解锁不再是"两只猫合成一只猫"——那套复用局内遗传表，语义与局内育儿窝重复，也不像"我在收集朋友"。改为两条独立轨道：局内每波次每只成年猫 20% 掉自己品种的绒毛；局外攒够某一只（高稀有目标则两只）**已入住**伙伴的绒毛与罐头，就让它们出门把新朋友请回来。新增 `Invite` 表承载，局内育儿窝保持不动，解锁演出沿用原图鉴揭晓页。详见 §5。 |
| D10 | **猫咪招募与自然绒毛**（2026-08-19） | 局外「猫咪小窝」正式更名为「猫咪招募」。每个已认识品种按现实时间自然积攒绒毛，默认每 60 分钟 +1、自然补到 12 撮为止；营业掉落仍保留且可超过自然上限。第一次营业回到大厅时优先提示绒毛入口。参数全部来自 `Settings`。 |

## 2. 猫咪图鉴

### 2.1 条目结构

每只猫一条图鉴（数据来源 `cats.csv`，见 DataTableSpec）：

```
┌─────────────────────────────┐
│  [头像 256×256]              │
│  名称        稀有度          │
│  发现次数：N                 │
│  来源：初始 / 繁育配方 / 变异 │
│  局内效果（rule_text）       │
│  性格 / 图鉴风味文案          │
│  等级：Lv1 ●○○  [培养]       │
└─────────────────────────────┘
```

未发现的猫显示为**剪影 + 来源提示**（"由两只毛色相同的猫繁育而来…"），提示文案填在表里，给玩家可追逐的谜面。变异猫的剪影不给提示（稀缺感）。

### 2.2 发现规则

- 触发点：局内 `SettleBreeding` 产出幼崽的瞬间。
- **首次发现**：全屏发现演出（"新猫咪！"）+ 图鉴解锁 + 局末罐头折算 +20。
- **重复发现**：只累计"见过 ×N"。绒毛与重复发现无关，由营业掉落与现实时间自然增长独立累计（D9，见 §5.1）。
- 发现立即写盘——玩家中途退出不丢收集进度。
- 局外呼朋唤友请来的猫走同一个发现入口，因此也享有同一套图鉴揭晓演出。

## 4. 奖励池联动（闭环的命门）

```
局内奖励池 = 基础池（表中 unlock=base 的条目）
           + 图鉴已解锁品种的成年形态（按表中 pool_rarity 入池）
```

- 未发现的品种**绝不**出现在三选一里——保证"发现"的仪式感。
- 每解锁一只猫，下一局的构筑空间实际变大，这是"填图鉴"的玩法回报（不只是相册）。
- 首局体验与现版几乎一致（普通池微调：移出燕尾服/奶牛/三花后，用灰虎斑保底）。

## 5. 绒毛与猫咪招募 · 呼朋唤友（保底轨道，2026-08-19 更新）

> 本节取代原「材料与繁育室」。旧方案是局外拿双亲绒毛"两只猫合成一只猫"，
> 与局内育儿窝是同一套配方的两个入口，语义重复且和"我在收集朋友"的定位不符。
> 现改为：营业时掉绒毛，局外按现实时间自然积攒；在猫咪招募中让已入住的猫
> **出门把朋友请回来**。

### 5.1 绒毛（营业掉落 + 现实时间自然增长）

```
每波次结束时，盘面上每只成年猫各判一次：
  meta_fur_drop_chance（默认 20%）→ 该猫品种绒毛 +1

每个已认识的猫品种按现实时间结算：
  每 60 分钟 +1 撮，自然增长最多补到每品种 12 撮
  间隔、单次数量、上限全部由 Settings 配置
```

- 只算成年猫（`kind=cat`）。幼崽不掉毛——否则图鉴还没点亮的品种会先攒出材料。
- 幼崽、客人、餐饮、用品、员工都不掉毛。
- 每波次掉完立刻写盘：玩到一半退出，已经掉下来的绒毛不能白掉。
- 现实时间增长保留不足一个间隔的余数；旧存档从升级后的首次加载开始计时，不追溯补发。
- 自然增长只补到配置上限，营业掉落不受该上限截断。
- 绒毛**只影响局外**，不进入任何局内数值。

设计意图：主动营业是更快的绒毛来源，现实时间增长提供稳定保底。第一次结束营业回到大厅时，
房东奶奶优先提示玩家去猫咪招募查看绒毛。

> 改造前的三条来源（繁育掉毛 / 重复发现 / `material_bonus` 翻倍）**一条都没实装**，
> `AddFur` 全项目零调用，导致局外解锁面板的每个按钮永远是灰的（2026-08-15 审计发现）。
> 现统一收敛为上面这一条，`material_bonus` 的归属留待亲密度实装时再定。

### 5.2 呼朋唤友（Home 内「猫咪招募」面板）

```
呼朋唤友 = 邀请者A的绒毛 ×fur_a
         [+ 邀请者B的绒毛 ×fur_b]     ← 越稀有的猫要的邀请者越多
         + 罐头 ×cans
产出     = 直接点亮该品种图鉴（不产局内幼崽）
```

规则要点：

- **邀请者不是父母**。它们是已经住进猫咖的猫，带着绒毛和罐头出门，把新朋友领回来。
  谁能请到谁由 `Invite` 表定，与局内遗传表（`Breeding`）完全无关。
- 邀请者必须**已经入住**（图鉴已点亮）——没解锁的猫叫不动。
- 目标稀有度决定邀请者数量：uncommon 一位，rare 两位（表驱动，不写死在代码里）。
- **变异猫（异瞳、德文卷毛）不进表**——只能在营业时偶遇，保持稀缺。
- 解锁演出复用与局内诞生完全相同的图鉴揭晓页，不另做一套。

当前 12 条邀请（详见 `Invite` 表），解锁链从四只初始猫出发两轮铺满：

| 轮次 | 请到 |
| --- | --- |
| 第 1 轮（1 位邀请者，base 猫的绒毛即可） | 蓝猫、燕尾服、暹罗、橘白、狸花、玳瑁 |
| 第 2 轮（奶牛 1 位；其余 rare 均 2 位） | 奶牛、三花、英短、金渐层、布偶、长毛 |

局内育儿窝**保留不动**：它仍然是"惊喜"那条轨道（还带变异位），
呼朋唤友是"进度条"那条轨道。两条各自独立，殊途同归。

## 6. 猫咪亲密度（2026-08-13 重写，取代购买式等级；决策 D4–D7）

> 猫猫负责让玩家想回来，构筑负责让玩家想再开一局；
> 局外成长应该增加新的可能，而不是替玩家赢下游戏。

**设计判断**：局外一定需要猫，但不需要"花罐头让猫永久 +10%"。购买式纵向升级的四宗罪：
新玩家被迫刷局外数值才能通关；失败被归因为"等级不够"而非构筑问题；玩家固定使用
练度最高的猫、削弱三选一；后续关卡只能跟着数值膨胀。因此改为**收集 + 亲密度 + 横向解锁**。

### 6.1 亲密度获取（D4）

| 事件 | 亲密度 | 说明 |
| --- | --- | --- |
| 该猫本局上过场且完局（同行） | +1 | 主线：玩就会涨 |
| 首次发现 | +2 | 与新发现弹窗同时刻 |
| 繁育出它的后代 | +1 | 双亲各计 |
| 喂食（罐头，表配置价格与冷却） | +1 | 辅线兼罐头 sink，冷却防氪空气 |

### 6.2 里程碑（全品种统一模板，D7）

| ❤ | 解锁 | 实现落点 |
| --- | --- | --- |
| 1 | 入住猫咖（发现即 ❤1），大厅游走 | 现状已有 |
| 2 | 一段故事 + 新的大厅动作 | `dex_flavor` 列 + 大厅行为状态 |
| 3 | 该猫的联动提示（局内规则揭示） | `dex_hint` 列分级揭示，零新数据 |
| 4 | 外观 / 家具互动（二期占位） | 挂装修系统 |
| 5 | 随行特性（横向，见 6.3） | 表配置 + 少量代码 |

### 6.3 随行猫（D6）

开始营业前从入住猫中指定**一只**随行：

- 获得上场抽样加权（复用已实现的 `board_weight` 通道，改为仅随行猫生效）；
- 该猫 ❤5 特性生效。特性必须是横向选择，示例：
  "本局首次遇到燕尾服猫时免费重抽一次"、"开局预览一只与它有联动的猫"、
  "燕尾服猫被跳过后，提高客人类出现概率"。**禁止**"每级多产 N 金币"式数值。

一次只有一只随行，防全队叠被动；这也吸收了原二期 backlog 的"镇店猫"。

### 6.4 迁移（D5）

- `mutation_up`、`material_bonus` → 平移为 ❤3/❤4 档位效果（本就作用于概率与产出）；
- `board_weight` → 随行猫限定（局内 `BuildBoard` 加权代码已在，改判定条件即可）；
- levels.csv 罐头/绒毛消耗列**作废**，绒毛回归纯解锁材料，由营业掉落和现实时间自然增长产出、猫咪招募消耗（§5 同步更新）；
- 图鉴的"升级按钮" → 亲密度进度条 + 分级揭示。

### 6.5 MVP 切片

做：intimacy 表 + 存档字段、三个获取打点、图鉴亲密度进度条与 `dex_hint` 揭示、
随行猫选择、大厅喂食。**不做**：全品种特性覆盖（仅 3–5 只基础猫）、生活表现深模拟、
外观解锁。验证目标：玩家是否为了猫反复开局。亲密度变化必须在 RunSummary 结算页
亮相（"小黑 ❤+1，还差 2 次同行解锁新故事"）——回家仪式与亲密度是同一条流水线。

## 7. 局外货币：罐头

| 货币 | 范围 | 用途 |
| --- | --- | --- |
| 金币 | 局内 | 付房租（现状不变，局末不带出） |
| **罐头** | 局外 | 喂食（亲密度辅线，2026-08-13 取代购买式升级）、呼朋唤友、（二期）装饰购买 |

局末折算（RunSummary 结算页展示明细）：

```
罐头 = ⌊剩余金币 × 20%⌋
     + 完成关卡数 × 10
     + 本局首次发现数 × 20
     + 失败保底：⌊本局总回合数 / 2⌋   （只在未完成任何关卡时生效）
```

失败保底必须有——"这局虽然没过，但攒了点罐头、还摸到一只重复猫"是继续开下一局的理由。

## 8. Home 猫咖大厅（实景版，2026-08-08 按店长反馈升级）

> 原方案是"三个静态展示位"；反馈后升级为**实景猫咖**——收集的猫是活的，不是相册。

```
┌──────────────────────────────────────────┐
│ 🪟窗  ═══货架═══                          │
│        ┌─────────┐            🫙          │
│  🐈←→  │  ☕吧台  │   🐈‍⬛←→    收钱罐      │
│    🛏育儿窝  🍚猫粮碗  🚽猫砂盆  ↑点击收取   │
│  ～～～～～ 地毯 ～～～～～                  │
│  ┌────────┐ ┌────────┐ ┌──────────────┐  │
│  │  图鉴   │ │ 猫咪招募  │ │  开始营业 ▶  │  │
│  └────────┘ └────────┘ └──────────────┘  │
└──────────────────────────────────────────┘
```

- **已收集的猫全员在大厅游走**（随机走停、转向翻面、点击弹出名字/等级气泡），
  收集进度直接体现为店面热闹程度——这就是收藏的情感回报。
- **家具陈列**：育儿窝、猫粮碗、猫砂盆、吧台、货架（复用局内元素美术；二期接装修系统）。
- **收钱罐（放置收益）**：店里的猫持续攒小费，`jarRate` 罐头/分钟·每只猫（默认 0.2），
  上限 50 罐头封顶（防挂机滚雪球），点击收取。离线累积按上次收取时间结算。
  ——数值在调参面板可调，正式定案后进 DataTableSpec。
- 图鉴、猫咪招募是 Home 场景内的 overlay 面板，不单独开场景。

## 10. MVP 切分与验收

按闭环最短路径排序（技术里程碑对应 TechDesign §7）：

| 步 | 内容 | 验收标准 |
| --- | --- | --- |
| 0 | 存档 + 数据表地基 | 行为与现版一致；杀进程重开数据不丢 |
| 1 | 图鉴 + 发现打点 | 局内繁育出新品种 → Home 图鉴点亮 |
| 2 | 奖励池按图鉴过滤 | 未发现的猫不出现在三选一；解锁后出现 |
| 3 | RunSummary：罐头折算 + 绒毛 | 失败局也有结算页和保底收益 |
| 4 | 猫咪招募 | 绒毛攒够即可保底解锁；解锁演出复用图鉴揭晓页 |
| 5 | Home 展示间 | 三个展示位可换猫 |

**闭环成立判据**（第 2 步完成时验证）：一个新玩家在 3 局内能自然经历
"繁育出第一只新猫 → 图鉴点亮 → 下一局三选一里遇到它成年形态" 的完整链条。
